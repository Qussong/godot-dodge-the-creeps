# repo-sync

단일 `main` 브랜치로 운영하는 저장소를 원격과 맞추는 워크플로다. 사용자가 이 스킬을
호출한 것 자체가 "커밋하고 푸시해도 좋다"는 명시적 허락이다. **브랜치를 새로 파지 말고
현재 브랜치(`main`)에서 바로 작업한다.**

> 기본 브랜치가 `main`이 아닌 저장소에서는 아래 명령의 `main`을 그 저장소의
> 기본 브랜치 이름으로 바꿔 읽는다.

## 절차

1. **현황 파악**
   - `git fetch origin`
   - `git status --porcelain` — 로컬 변경 유무
   - `git rev-list --left-right --count origin/main...HEAD` — 앞/뒤 커밋 수

2. **경우 나누기**
   - 로컬 변경 없음 + 원격도 안 앞섬 → "이미 최신, 변경 없음" 보고하고 종료.
   - 로컬 변경 없음 + 원격이 앞섬 → `git pull --rebase origin main` 후 받은 커밋 요약, 종료.
   - 로컬 변경 있음 → 3번으로.

3. **변경 내용 확인**
   - `git add -A`
   - `git diff --cached --stat` 로 추가/수정/삭제 파일 목록을 확인하고, 그 목록을
     사용자에게 보여준다.

4. **커밋 메시지 작성** (아래 "커밋 메시지 규칙" 참고)

5. **커밋**

   ```
   git commit -m "<메시지>" -m "Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>"
   ```

6. **원격 반영** — `git pull --rebase origin main`
   - 충돌이 나면 **자동으로 해결하지 말고 멈춘다.** 충돌 파일 목록을 사용자에게
     알리고 지시를 기다린다.

7. **푸시** — `git push origin main`

8. **결과 보고** — 받은 커밋 수, 새로 올린 커밋 해시와 메시지 한 줄.

## 커밋 메시지 규칙

- **접두사 없이 한국어 내용 요약** 한 줄. (해당 저장소의 기존 커밋 히스토리 스타일과 통일)
- 동작별로 묶어서 쓴다:
  `추가: <파일명> · 수정: <파일명>, <파일명> · 삭제: <파일명>`
  - 파일명은 확장자와 폴더 경로를 뺀 이름만.
  - 한 종류가 3개를 넘으면 대표 1~2개 + `외 N건`.
- 내용상 의미가 뚜렷하면 파일명 나열 대신 무엇을 했는지로 쓴다.
  예: `설정 노트 추가, README 구조 개편`
- 공백/오타 수준의 사소한 변경만 있거나 요약이 무의미하면 폴백:
  `repo sync: YYYY-MM-DD HH:MM`
- 본문(둘째 `-m`)은 `Co-Authored-By` 트레일러만. 세션 URL은 넣지 않는다
  (반복 동기화 커밋에는 불필요).

## 주의

- 현재 브랜치에서 직접 커밋·푸시하는 것이 이 워크플로의 의도다.
- rebase 방식으로만 pull 한다 (머지 커밋 생성 금지).
- 커밋·푸시 전에 변경 파일 목록을 반드시 사용자에게 보여준다.
- 충돌은 자동 해결하지 않고 멈춰서 사용자에게 넘긴다.
- `.claude/settings.local.json` 등 `.gitignore` 대상은 신경 쓸 필요 없다.
